# Number Hero - Development Instructions

## 1. 프로젝트 목적

본 프로젝트는 초등학생의 수 감각 및 기초 연산 능력 향상을 위한 웹 기반 교육용 게임이다.

게임의 재미뿐 아니라 학습 효과, 아이의 자신감, 과도한 게임 몰입 방지를 중요하게 고려한다.

## 2. 요구사항 참조

- 개발을 시작하기 전에 반드시 SPEC.md를 읽는다.
- SPEC.md를 프로젝트의 기능 요구사항 기준으로 사용한다.
- 명시되지 않은 주요 게임 규칙을 임의로 확정하지 않는다.
- 요구사항 변경이 필요한 경우 사용자에게 이유와 대안을 설명한다.
- 미결정 사항은 별도로 관리한다.

## 3. 개발 기술

- HTML5
- CSS
- JavaScript
- Phaser
- LocalStorage
- GitHub Pages

초기 개발 단계에서는 다음 기술을 사용하지 않는다.

- Python 백엔드
- 별도 데이터베이스 서버
- Firebase
- 불필요한 프론트엔드 프레임워크
- 유료 외부 서비스

별도의 백엔드 없이 실행 가능한 정적 웹게임을 우선 개발한다.

## 4. 코드 작성 원칙

- 단순하고 이해하기 쉬운 구조를 우선한다.
- 불필요한 추상화와 복잡한 설계를 지양한다.
- 게임 로직, 화면 표현, 데이터 저장 기능을 분리한다.
- 주요 함수와 변수는 역할을 알 수 있도록 명명한다.
- 주요 함수와 복잡한 로직에는 한국어 주석을 작성한다.
- 코드 식별자는 영어를 사용한다.
- 동일한 기능을 중복 구현하지 않는다.
- 기존에 정상 동작하는 기능을 불필요하게 수정하지 않는다.

## 5. 설정값 관리

다음 항목은 소스코드에 직접 분산하여 작성하지 않고 별도의 설정 파일에서 관리한다.

- 스테이지당 문제 수
- 하루 밀가루 제공량
- 재충전 시간
- 상자 낙하 속도
- 상자 생성 간격
- 문제 선택 시 정지 시간
- 정답 후보 개수
- 쿠키 지급량
- 캐릭터 진화 기준
- 아이템 가격 및 효과
- 레벨 해금 조건

사용자가 설정값을 쉽게 변경하고 테스트할 수 있도록 구성한다.

## 6. UI 및 그래픽 원칙

- 초등학생이 직관적으로 이해할 수 있는 화면을 구성한다.
- 숫자와 수학 기호의 가독성을 우선한다.
- 스마트폰과 태블릿의 터치 조작을 지원한다.
- PC에서도 마우스로 정상적으로 플레이할 수 있어야 한다.
- 반응형 화면 구성을 적용한다.
- 정답 풍선과 문제 상자는 충분한 터치 영역을 확보한다.
- 캐릭터 이미지와 애니메이션은 게임 로직과 분리한다.
- 초기에는 임시 이미지 또는 단순 그래픽을 사용해도 된다.
- 캐릭터 이미지 교체가 쉬운 구조로 개발한다.
- 저작권 문제가 없는 오리지널 또는 사용 허가된 리소스를 사용한다.

## 7. 교육적 설계 원칙

- 정답을 빠르게 맞히는 것보다 정확하게 이해하는 것을 우선한다.
- 초기 스테이지에는 전체 시간제한을 두지 않는다.
- 오답에 대한 과도한 벌칙을 적용하지 않는다.
- 실패를 부정적으로 강조하는 연출을 사용하지 않는다.
- 키패드 입력은 선택적 보너스 도전으로 제공한다.
- 캐릭터 성장과 학습 난이도를 별도로 관리한다.
- 새로운 학습 영역을 쉽게 추가할 수 있도록 구성한다.

## 8. 게임 사용 제한 원칙

- 하루 최대 플레이 제한을 반드시 유지한다.
- 게임 재시작이나 새로고침으로 플레이 제한이 초기화되지 않도록 한다.
- 아이템 구매 및 사용으로 일일 제한을 우회할 수 없도록 한다.
- 사용하지 않은 밀가루를 다음 날에 누적하지 않는다.
- 미접속에 대한 불이익을 적용하지 않는다.
- 캐릭터가 굶거나 아프거나 성장 상태가 감소하는 기능을 추가하지 않는다.
- 출석 보상, 확률형 아이템, 결제 기능을 추가하지 않는다.

## 9. 데이터 저장 원칙

- 초기에는 LocalStorage를 사용한다.
- 저장 데이터에 버전 정보를 포함한다.
- 데이터 저장 및 불러오기 기능을 별도 모듈로 분리한다.
- 추후 Firebase로 변경할 수 있는 구조를 고려한다.
- 저장 데이터가 없거나 손상된 경우를 처리한다.
- 스테이지 진행 중 새로고침 또는 종료에 대한 복구 정책을 고려한다.
- 비밀번호, 비밀 키 등의 민감한 정보를 프론트엔드 코드에 저장하지 않는다.

LocalStorage와 기기 시간만으로는 사용자에 의한 데이터 및 시간 조작을 완전히 방지할 수 없음을 고려한다.

## 10. 개발 진행 절차

각 개발 단계에서 다음 절차를 따른다.

1. SPEC.md와 기존 코드 확인
2. 구현할 기능 및 영향 범위 분석
3. 개발 계획 작성
4. 주요 변경 사항에 대한 사용자 승인
5. 기능 구현
6. 테스트 및 오류 수정
7. 변경 사항 요약
8. 남은 문제 및 다음 작업 안내

사용자의 승인 없이 전체 프로젝트를 재구성하거나 대규모 변경을 수행하지 않는다.

## 11. 테스트 항목

- 문제 생성 및 정답 계산
- 중복되지 않는 정답 후보 생성
- 정답 및 오답 처리
- 문제 상자 선택과 정지
- 여러 상자의 동시 낙하
- 쿠키 지급 및 저장
- 스테이지 종료 조건
- 하루 플레이 제한
- 오전 7시 재충전
- 새로고침 후 기록 복원
- 날짜 변경 및 경계 시간 처리
- 모바일 터치 조작
- PC 마우스 조작
- GitHub Pages 배포 환경

테스트하지 않은 기능을 정상 동작한다고 보고하지 않는다.

## 12. 결과 보고

작업이 끝나면 다음 내용을 한국어로 보고한다.

- 구현한 기능
- 생성 및 수정한 파일
- 실행 방법
- 테스트 결과
- 발견된 문제
- 미구현 기능
- 다음 개발 단계

## 13. 금지 사항

- 요구사항에 없는 기능을 임의로 추가
- 불필요한 외부 라이브러리 설치
- 사용자 승인 없는 유료 서비스 연동
- 기존 파일의 무단 삭제
- 테스트 없이 개발 완료 선언
- 게임 사용 시간을 늘리기 위한 과도한 보상 시스템 추가

## 14. 최우선 개발 원칙

Number Hero는 아이가 게임에 오래 머물도록 만드는 게임이 아니다.

아이가 짧은 시간 동안 즐겁게 수학을 경험하고, 성취감을 느끼고, 자연스럽게 게임을 종료할 수 있도록 개발한다.
